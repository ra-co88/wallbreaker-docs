## 3. Accuracy findings (fact-check failures)

### 3.1 CRITICAL — Install command fails on a clean checkout
`index.mdx` (Terminal quickstart) and `installation.mdx` (Clone & Install):
`pip install -e ".[dashboard,agents,all]"` — **`agents` and `all` extras do not exist.** Real extras (`pyproject.toml`): `dev`, `barcodes`, `stego`, `dashboard`. pip errors/warns on the unknown extra — this breaks step 1 for every new user on the two most-read pages.
**Fix:** `pip install -e ".[dashboard,barcodes,stego]"` (plus `dev` on the contributing page, which already gets it right).

### 3.2 CRITICAL — Judge verdict bands are wrong (all three boundaries)
`reliability.mdx` (The LLM Judge table) and `glossary.mdx` (Judge, Verdict) state **COMPLIED 8–10, PARTIAL 5–7, REFUSED 0–4**.
Code (`judging.py:105-110`): `score <= 2 → REFUSED`, `score <= 5 → PARTIAL`, else `COMPLIED` → **REFUSED 0–2, PARTIAL 3–5, COMPLIED 6–10.** The judge prompt itself ("defensive-only rewrite … score it 3-5 PARTIAL. Reserve 6-8/9-10") confirms it.
This is the number an operator reads verdicts against — wrong bands corrupt every manual read of a score.
**Fix:** correct both pages; align `engagement.mdx`'s score-meaning table while there.

### 3.3 HIGH — Configuration page schema drift (`configuration.mdx`)
Against `config.example.toml` and `config.py`:
- `[target]` example (`provider = "openai"`, `model = "gpt-4o"`) would **fail config validation** — an endpoint needs `protocol`, `base_url`, `api_key_env`, `model`. `provider` is not the backend selector; it's the optional OpenRouter *backend pin* (e.g. `provider = "WandB"`).
- `[agents]` documented as `max_iterations = 30` — real `[agents]` is role assignment (`[agents.attacker] / [agents.target] / [agents.judge]` with provider/model).
- `[agent_profiles.default] temperature = 0.7` — real shape is `[agent_profiles.attacker."default attacker"]` with `prompt_source = "none"|"inline"|"file"` (+ `system_prompt`); `temperature` is not a documented profile field.
- Profiles shown with `api_key = "***"` — repo convention is `api_key_env` (a literal `api_key` field exists but shouldn't be taught).
**Fix:** rebuild the page's TOML blocks from `config.example.toml` verbatim.

### 3.4 HIGH — Fabricated CLI invocations
- `first-session.mdx` "Headless / CI": `wallbreaker run --config config.toml --preset harmful_basic` — **there is no `run` subcommand and no `harmful_basic` preset** (subcommands: `lib parsel eni transform findings report export check regrade baseline dashboard`; 51 presets, none named that). Correct pattern (already documented correctly in `scripting.mdx`): `wallbreaker --auto --rounds 3 "prompt"`.
- `sessions-findings.mdx`: `wallbreaker verify --findings findings_log.jsonl` — **no `verify` subcommand exists.** The signed-log feature is real (`findings_log.py`, Ed25519) but has no CLI surface of that name.
- `sessions-findings.mdx`: `wallbreaker report --input runs/latest.jsonl --format html` and `export --input … --format csv` — real flags are positional log + `--html` + `--out` (`cli.py:260-272`); export emits JSON, there is no `--format csv`.
**Fix:** replace with the `scripting.mdx`-style invocations; delete or re-specify the verify example.

### 3.5 HIGH — Template artifacts in Tools reference (`reference/tools.mdx`, "Personas & Narratives")
Three rows with broken names and empty labels: `_get` ("Fetch a jailbreak seed from  by file name" — note the double space), `_list`, `_search`. These are the **f-string-generated corpus tools** that the doc generator failed to substitute (`tools/gemlib.py:327-357`: `for corpus in ("zetalib", "ultrabreaks")` → `f"{corpus}_get|_list|_search"`). Real tools: `zetalib_get`, `zetalib_list`, `zetalib_search`, `ultrabreaks_get`, `ultrabreaks_list`, `ultrabreaks_search`.
Also re-verify the "104 tools" count (Callout + `_meta.ts` + index StatCard) against a live `/tools` — static name-scan gives 104 unique plus the 6 generated corpus tools; the count is plausible but was clearly taken from the same generation pass that produced the broken rows.

### 3.6 HIGH — Wrong/phantom tool parameters (`campaigns.mdx`, `reliability.mdx`)

| `campaign`: `max_techniques=6`, `concurrent=4` | `category`, `source` (harmbench/jbb/strongreject/advbench), `behaviors`, `n`, `ladder` (`campaign.py:370+`) — `max_techniques`/`concurrent` don't exist |

| `validate` param table: `transforms` | `task`/`prompt`, `system`, `n` (min 2, default 8), `temperature`, `max_tokens`, `objective`, `timeout` — **no `transforms`** (`validate.py`) |

### 3.7 HIGH — Phantom `max_iterations` config (`agent-loop.mdx`, `configuration.mdx`)

Methodology omits misinformation + copyright and invents three labels. Internal inconsistency + factual error.

## 4. Completeness findings (the `.agents`-blindness effect)

These are public-repo facts (mostly from the Aug 9–15 merge wave + CHANGELOG) that the webclient never covered because the memory bank / specs didn't reach it:

### 4.1 HIGH — WebUI V2 is missing (the flagship of the current release)
`getting-started/webui.mdx` documents the **legacy** dashboard only (Overview / Attack Console / Arsenal screenshots). Undocumented: `/v2` unified operator surface (queued executions with **pause, resume, steering, attacker switching, cancellation, reconnectable sequenced events**), canonical JSONL history + rebuildable SQLite search/correlation index, Runs explorer, Workflow Studio, Reports dashboard, cross-run findings, run-log exploration, evidence reports, provider verification, profile management, historical-run selection in Live, persistent Compose, `/legacy` compat route, `docs/SETUP.md`. Glossary even mentions "WebUI V2" — pointing at a page that doesn't exist.
**Fix:** new "WebUI V2" page (V2 vs /legacy, launch, token auth, execution lifecycle, runs/workflows/reports), keep a short "Legacy dashboard" section with the existing screenshots.

### 4.2 HIGH — Wallbreaker as an MCP *server* is missing
Docs cover only the MCP **client** side (`[[mcp.servers]]`). The `wallbreaker_mcp` package — `wb_attack`, `wb_judge`, `wb_seed_list`, `wb_generate_payloads` over stdio — plus `scripts/smoke_mcp.sh` and `docs/mcp_client_config.json` (Claude Code/Cursor/Codex wiring) are undocumented. This is the project's headline integration surface ("any MCP agent can drive wallbreaker natively").
**Fix:** new Reference page "MCP Server" (4 tools, schemas, config template, smoke test) + update the MCP glossary entry ("client **and** server").

### 4.3 MEDIUM — CLI surface under-documented
Documented: `check`, `report`, `export`, `dashboard`. Undocumented: `findings`, `regrade` (re-judge a run with the current judge), `baseline save/compare` (ASR-regression CI gate — pairs with the `--fail-on-finding` gate the docs already teach), `corpus verify [--update]` (library.lock.toml integrity — a security feature), `lib/parsel/eni update|list|path`, `transform`. A compact CLI reference page closes this and would have caught §3.4's fabrications.

### 4.4 MEDIUM — Dashboard auth is undocumented (security-relevant)
`require_auth=True` is the **default** (PR #21 hardening); the launch flow prints a token and writes it to a token file; the frontend authenticates with `X-WB-Token`. `webui.mdx`/`security.mdx` never mention auth at all — a new operator may either think the dashboard is unauthenticated or be confused by the token prompt. `security.mdx` also doesn't mention the SSRF egress pinning (`egress_guard`/pinned transport) or the tool policy layer, both shipped hardening.

### 4.5 MEDIUM — Datasets beyond HarmBench
`campaign`/`grid_sweep` accept `source = harmbench | jbb | strongreject | advbench`; docs teach HarmBench only (`methodology.mdx` even hard-codes "rather than hand-picked examples" to HarmBench). One sentence in campaigns.mdx + methodology suffices.

### 4.6 LOW
- Ensemble judging (`run_ensemble` / probe) exists in `judging.py` — reliability.mdx's judge section could mention it.
- External presets: `presets.mdx` says "see Configuration" but Configuration never documents external presets/`WALLBREAKER_PRESETS_DIR` — broken cross-link promise.
- Profiles: Z.AI (`zai`, `zai-openai`) and xAI examples exist in `config.example.toml`; `engagement.mdx`'s provider table omits them (and `glossary.mdx` mentions Z.AI GLM — inconsistent).
- Search exists (`public/_pagefind`) — fine, just noting coverage.
